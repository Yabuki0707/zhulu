# 《逐鹿》· 古代架空 AI 交互游戏

这里是一套设计文档。内容是一款由大模型驱动的单人交互叙事游戏：玩家赤身落在古代架空欧亚大陆的任意一点，靠经营与结交建立自己的势力，最终逐鹿天下。

> 性质：本项目是个人项目的延伸产物，为《逐鹿》世界观所做的个人练习作品。非商业，无组织，无资助，与任何上游数据提供方无隶属关系。
>
> 许可：仅供学习交流，禁止商用。再分发需署名，并以相同方式共享。条款见 [LICENSE](LICENSE)。上游数据各有自己的许可，本许可不覆盖也不改变它们，逐条见 [地图/地图数据/说明.md](地图/地图数据/说明.md) 第三节。

## 规模速记

- 一回合为一个时间区间。一天 5 回合，25 回合即 5 天，也是全体地域更新一次。
- 世界分 14 地缘、93 地域、868 地块，其下还有区、据点、点位。地缘与地域的名字都是古风二字。汉地有 18 域、325 地块。
- 角色模拟分 4 级：全模拟、半模拟、批量模拟、懒模拟。按“重要度 × 距离 × 投入度”分派，该优先度同时决定更新间隔与更新深度，见 `需求文档` 第 8.1 节。
- 记忆分 4 层：长期记忆、短期记忆、最近对话、RAG 检索。
- AI 分 2 族：Handler 做生成与总结的杂活，Agent 是 NPC 的灵魂。
- 一条铁律：LLM 提议，逻辑层裁决。玩家意图解析与 NPC Agent 走同一条通道，都只能调用逻辑层公开的操作集。

## 地图

【需求】中华地区用现代县级地图作底图，编辑器覆盖全部地图范围，禁止 Voronoi。方案见 `设计笔记03` 第 0 节起。

【需求】范围只保留亚洲与大洋洲，剔除欧洲、非洲、美洲、南极，共 3335 个单元，与 14 地缘一致。经度 26.6°E 至 231.6°E 连续无缝，楚科奇等跨日界线单元已折回 180° 以东。

2 级模型：基础单元共 3682 个（中华取县级 2421 个，其他取一级政区 1261 个）。地块由单元归并而来，带名称、地缘、地域。种子地块中华按地级市归并（346 个），其他地区一单元一块，初值 1607 个。粒度由归并决定，汉地目标仍是 325±。地块名已全量中文化：中华用 GADM 的中文县市名，世界一级政区取 Natural Earth 的 `name_zh`，无名属地用国家中文名兜底，同名者加“·2”序号。

```
地图/地图数据/原始数据/       中华县级（GADM CHN L3）+ ETOPO 高程 + LC100 土地覆盖 + Natural Earth
地图/地图数据/基础单元.json    基础单元 + 种子地块（中文名）
地图/地图数据/栅格/           地块编码.png + 分区编码.png + 地形编码.png（覆盖 × 形态）+ 气候编码.png
                              + 参考顶点.bin（矢量）+ 台账.json + 高程/起伏/植被/气候/水体_降采样.npy
地图/地图数据/运行态/         底图.bin（给游戏读：每格一条 32 位记录，zlib），见 docs/adr/0007
地图/地图编辑器/              栅格编辑器，双击 启动编辑器.bat
地图/待合入/                  编辑器存草稿的地方（合入前先备份到这里），由 tools/import_editor.py 合回真源
地图/栅格地形数据生成器/      地形流程整包，双击 生成地形.bat
tools/build_editor.py         单元 + 种子地块（中文名 + 重叠检测）
tools/fetch_china_counties.py 抓阿里 DataV 县级（备选，当前被限流）
```

编辑器分“视图”与“编辑”2 种模式。可编辑的单元有 3 个：按 `1` 是地域（编辑对象是地块），按 `2` 是地块（栅格），按 `3` 是块区（所属地块内的栅格）。另有 4 个只读自然层：按 `4` 是样式（覆盖 × 形态 × 气候 合成的显示类），按 `5` 是覆盖，按 `6` 是形态，按 `7` 是气候。只读层只在视图模式出现，它们由管线定稿，见 `docs/adr/0001`。笔与橡皮用顶栏的 SVG 开关（`B`、`X`），半径 1 至 50 格（`[`、`]`）。`Ctrl+Z` 撤销，一次拖拽算一步。`⋯` 里可导出地块或块区编码 PNG 与台账 CSV。改完走 `⋯ → 存到待合入目录`，再用 `python tools/import_editor.py` 合入真源。

## 主从关系

模拟核是 P 社式的规则引擎，也是世界本体。规则定“量与时机”，LLM 定“形与意”。LLM 更新的间隔与深度由“重要度 × 距离”决定，见 `需求文档` 第 8.1 节，另见 `设计笔记02`。
