# 造物只走校验、不走裁决；数值由规则从档次算出

`设计笔记02` §7 把"让 LLM 决定数值后果"列为反例，理由是"无法平衡、无法测试、玩家学不会规律"；但 `附录B` B6.2 的据点生成让 LLM 直接输出 `population`——两处打架。同时 `设计笔记02` §9 收尾图称交界处只有"事件槽"与"提议"两个，造物这条通道无处安放。

决定：造物（据点、NPC 骨架、地名等一次性生成的物，即 `设计笔记01` 五入口里的 ⑤ 生成器）是**第三条交口——固化**。LLM 只判**档次与类型**（山窝小寨／通衢大镇；城池／村庄／土匪窝），人口与规模等数字由规则按 **地形 × 局势 × 档次** 算出。造物输出仍须过**校验器**（数值区间、与地形相符、重名），但不经"要不要发生"的裁决——寨子该造就得造，没有可裁之问。

重名：**同一地块内不重名即可**，跨地块允许重名。名字不承担唯一性，uid 承担。

## Considered Options

- **LLM 直接写数值**（维持 `附录B` B6.2 现状）：否。数值一旦由模型生成就无法标定、无法回归，玩家也学不会规律。
- **造物也走"提议 → 裁决"**：否。造物没有"要不要发生"这一问，裁决层无从判断，走一遍只是形式。

## Consequences

- `设计笔记02` §9 收尾图须由"两个交界处"改为三个：**事件槽／提议／固化**。
- `附录B` B6.2 据点生成输出删去 `population`，改出 `scale`（档次）；B6.1 的重名约束由"不得与已生成地块重名"放宽为"同一地块内不重名"。
- 校验器成为造物的必经环节，与"提议"共用同一套 schema 与语义校验。
