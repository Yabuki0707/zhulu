# 底图数据契约 v9：覆盖扩到 5 位（加 海冰／咸湖／盐漠／火山 四类）

> **路径说明（2026-10-10）**：地形流程整包从 `tools/` 搬到了 `地图/栅格地形数据生成器/`
>（入口是 `生成地形.bat`，流程在 `管线.py` 的阶段表里）。本文里的路径已按新位置更新。

> **状态**：全部有效。覆盖 **16 → 20 值**、**4 位 → 5 位**；显示类 **81 → 88 类**；
> `display_lut` **2048 → 2560**。**运行态仍是每格 32 位**（一位没多）——多的那一位是从
> **地块**里借的（13 → 12 位）。地形字节仍是一个字节，只是解包从 `>>4 / &15` 变成 `>>3 / &7`。
>
> **§八、§九 是同一天追加的两轮**（都得需求方看过第一版之后才动的）：§八＝改名／海冰重做／
> 里海与渤海湾两条规则；**§九＝干涸的湖床回水（咸海，一条**判定**规则，位布局一个位没动）**，
> 以及**编辑器视图补上「样式」（改名）与「形态」（新只读层）**。所以这一份 ADR 里
> "覆盖位宽"只变过一次，其余都是规则与视图。

## 一、起因

需求方：**"地形覆盖增加一个 byte，增加海冰、内陆盐碱地／盐漠、沙滩、湖泊咸淡、火山"**，
以及**"视图增加覆盖与样式两种模式"**。

我先按"加一个字节"想，**是错的**：覆盖需要 16+5=21 个值，**5 位**（32 个位置）就够。
需求方一句"覆盖明明 + 一个比特不就好了"点破了。所以这次只动**一个比特**。

## 二、位布局（v9）

```
运行态 底图.bin（仍 32 位，一位没多）：
  覆盖 5 ｜ 形态 2 ｜ 热量带 2 ｜ 干湿 3 ｜ 地块 12 ｜ 块区 8  = 32
                                        ↑ 13→12（实测只用 1,602 个地块，12 位装 4,095）

地形编码.png（仍一个字节，不用拆）：
  字节 = 覆盖 × 8 + 形态      ← 覆盖高 5 位、形态低 3 位（形态只用 0–3，低 3 位里那 1 位留白）
  最大字节 = 31 × 8 + 3 = 251 < 256 ✓ ；海洋仍是 覆盖 0 ∧ 形态 0 = 字节 0 ✓
```

**新类一律追加在末尾（16 起）**，前面 0–15 的**码值一个不动** —— 于是植被层的缓存仍然有效
（里面存的就是覆盖码），省掉一次 1–2 分钟的重读。

### GLWD-3 的已知漏项

它是 2004 年的粗产品（30 弧秒）：**察尔汗、乌斯秋尔特、卢特、长芦盐场**都读成"非湿地"。
**命中很好的**：伊朗**卡维尔盐漠**、**罗布泊**（整格 25/25）。

⚠️ **因此「盐漠」这一类不会修掉渤海湾那排"湖泊"** —— 那是 LC100 把**长芦盐场**（天津汉沽—沧州黄骅，
全国最大海盐场）的蒸发池记成"内陆水体"、再经「内海转湖」变成湖泊造成的（实测那块 138 格"湖泊"
里 137 格来自 LC100 的内陆水体码；全图同类 2,051 格，扎堆在里海/咸海沿岸潟湖、渤海湾西岸、
北极沿岸潟湖）。要治它得加一条**贴海 ∧ LC100 内陆水体 → 盐沼/滩涂**的规则，**本次没做**。

## 八、追加（2026-10-10 晚，需求方看完第一版之后）

### 1. 「湖泊／咸水湖」改名「**淡湖／咸湖**」

需求方定。理由直白：**有了咸湖，就得有它的对应词**。**码值一个没动**（1 与 17），只改名字；
显示名同步：淡湖／高原淡湖、咸湖／高原咸湖。文档里凡指"覆盖/显示类"的地方都换了，
指"NE 湖泊层""湖泊面"这类通用说法的地方**没动**。

### 2. 海冰：改成"常年"，并做形态学清理

第一版用 **≥50% 的年份**有冰，需求方报**"质量太差、范围过广"**。实测与处置：

| 门槛 | 格数 | |
|---|---|---|
| ≥50% | 826,482 | 第一版 |
| ≥80% | 794,256 | |
| **=100%（现行，＝"常年"）** | **736,590** | 30 个 3 月里**每一年**都被冰盖住 |

- **范围**：位置实测是对的——拉普捷夫海/东西伯利亚海/喀拉海/鄂霍次克海都有冰，巴伦支海西南、
  白令海、挪威海无冰。所以"广"不是判错，是 NSIDC 的 **extent 本身含 15% 稀疏冰的边缘带**；
  把门槛改成"常年"能把那条毛边压薄。
- **质量**：25 km 的粗网格采样到 5.86 km 的格上，第一版有 **89 个连通域、60 个 <10 格的碎块、
  3 万个针孔**。现在做**形态学清理**（填 <200 格的洞、去 <50 格的碎块）→ **20 个连通域、0 碎块**。
  ⚠️ 这是**显示整形**、不是判据，写在 `地图/栅格地形数据生成器/ice.py` 的注释里免得下一个人以为毛边是数据本来的样子。
- 色板里海冰原来取 #dfeaf2，与冰川 #f9feff 太像，改成 **#a9cfe0**（ΔE 仍 ≥ 9）。

### 3. 里海里有"海洋" —— 两条新规则（需求方截图报的）

**症状**：里海整块是咸湖，但里面混着 **439 格"海洋"**；而"沧州、天津沿海那排湖泊"也没解决。

**根因是同一件事**：**NE 与 LC100 对水线的口径不一致**。
- 里海在 NE 里属**"海洋层"**（不在湖泊层）；旧版靠"LC100 说是内陆水体(80)"往回捞，可 LC100
  在里海的**浅滩**说那是陆地（草本湿地/草原/裸地）—— 于是那些格留在"海洋"里。
- 反过来，LC100 把**长芦盐场**（天津汉沽—沧州黄骅，全国最大海盐场）的蒸发池记成"内陆水体"，
  于是 NE 说是陆地的格读成了「湖泊」（实测那块 138 格，全图同类 2,051 格）。

**处置（三条规则）**：

1. **内海/大湖改用 GLWD-1 的湖面清单**当"什么算湖"的唯一口径（**不再依赖 LC100 的码**）。
   依据：GLWD-1 在窗口内 **1,285 个面、没有一个其实是海**（黑海/地中海不在里面）——它天生就是
   干这个的。实测 15,358 格由海洋改记湖泊。
2. **湖岸收口**：**被围住**（走不到窗口边界）、**≤3,000 格**、**8 邻接有湖**的"海洋"块 → 湖。
   依据：GLWD 的湖面是手绘面、**比湖略小**，里海东南角就缺一块（实测残留 704 格"海洋"）。
   黑海 **18,458 格**过不了 ≤3,000 这条 → **仍是海洋** ✓（它本来就是海）。
3. **咸淡按"水体整体"定**：把「淡湖 ∪ 咸湖」按连通域切开，**只要一块里有一格落在 GLWD 的闭合
   盆地湖面内，整块就是咸湖** —— 同一个湖不该一半咸一半淡。修的是里海东南角（它先被 LC100 兜底
   补成了淡湖）：实测 2,074 格由淡湖改咸湖。
4. **沿海盐田/潟湖 → 盐沼**：LC100 内陆水体 ∧ **距海 ≤2 格** ∧ 非 GLWD 湖 → **盐沼**
   （口径与既有的「碎水补面：离真河 ≤3 格」同一路）。实测 1,371 格。

**结果**（需求方报的两处）：
- **里海整片（含东南岸）都是咸湖**，周边框内已无"海洋"；**黑海仍是海洋** ✓。
- **渤海湾西岸的"湖泊"由 138 格降到 25 格**（那 25 格是真水库，如 NE 里具名的**北大港水库**），
  其余归**盐沼**。

### 4. 咸海读「砾质裸地」——**已由 §九 解决**，这里留问题原文

**咸海读「砾质裸地」**：LC100（2019 影像）看到的咸海是**干涸的湖床** → 裸地。GLWD-1（2004）
的咸海面还在，但我们的湖面清单**只作用于"当前是海洋"的格**，不覆盖陆地 —— 所以没把它改回湖。
这是"底图照今天的影像走"与"历史地图想要那片水"之间的取舍，**留待需求方定**（改起来就是让
GLWD 湖面也覆盖陆地，代价是会把今天已干涸的湖全改回水）。

→ **需求方 2026-10-10 拍了窄版**：只认 GLWD 的**湖**面（水库不算）、且今天必须读**沙/砾裸地或
草甸/草原**。见下面的 §九。

## 九、追加二（2026-10-10 深夜）：干涸的湖床回水；编辑器视图补上「样式」与「形态」

### 1. 干涸的湖床回水（咸海那一片）

**判据三条**（需求方从两个方案里挑的窄版）：

1. 落在 GLWD-1 的**湖**面内（`lakepoly == 1`）—— **水库面（`== 2`）不算**；
2. 今天的覆盖是**沙质裸地 / 砾质裸地 / 草甸 / 草原**（干了的湖床）；
3. 咸淡照旧（闭合盆地 → 咸湖，由既有那两步收口）。

**为什么要分"湖"与"水库"**（这是窄版的全部要害）：GLWD 的**水库面普遍画得比今天的水面大**
——布拉茨克 99 格、切博克萨雷 85 格、卡布拉巴萨 42、伏尔加格勒 16、萨彦舒申斯克 16。跟着它走
会把湖边的**真林子**变成假湖（实测宽的版本 4,266 格里 1,355 格是水库面内的，其中 **290 格密林**）。
所以 `地图/栅格地形数据生成器/glwd.py` 的湖面清单 **v2 起返回分型码**（0 非湖 / 1 湖 / 2 水库，取 `TYPE` 字段；
⚠️ 别用 `MGLD_TYPE`——那是**盆地属性**，2,326 个面在那儿是空的）。既有两处调用改成 `> 0` / `== 0`。

**实测**：命中 **2,833 格**（闭合盆地 2,395 → 咸湖，其余 438 → 淡湖；随后"咸淡按水体整体"
又并了 22 格进来）。逐面 top：**咸海 2,119**、乌尔米耶 27、巴伦托雷 26、萨贝里 25、
巴尔喀什 13、里海 9（那 9 格是里海北岸浅滩原来读裸地的格）。

**对 v9 成品逐格 diff**：共 **2,855 格**变（2,833 是本规则的 + 22 是水体整体定咸淡带出来的），
- **形态位一格没动**（规则只写覆盖那 5 位）；
- **海洋一格没动**（改的 2,833 格原本都是陆地）；
- **密林 / 疏林 / 灌丛 / 沼泽一格没动**（水库排除 ＋ "不碰活植被"这条一起保的）；
- 计数：砾质裸地 −2,085、草原 −599、草甸 −144、沙质裸地 −5 → 咸湖 +2,431、淡湖 +402。

**断言**（`地图/栅格地形数据生成器/check_terrain.py` 新增 6 条）：咸海（大/小）、乌尔米耶、巴伦托雷、巴尔喀什西半
→ **咸湖**；**布拉茨克水库那格仍是密林** —— 这一条就是守着"水库不算湖"。

**明确不做**：**绿洲**（覆盖 15）不进这条规则（实测只有 14 格）。它和"草甸"看着像同类
（都是耕地），但需求方给的判据是"裸地或草甸草原"，**不自作主张往外扩**；要并是一行的事。

### 2. 编辑器：视图补上「样式」与「形态」

- **「地形」只读层改名「样式」**。需求方两次问"视图层咋没加样式"：原来「覆盖」层的出现只把
  "覆盖与样式两模式"做掉一半，另一半我当成了**已有的「地形」层**——而他们认的是**顶栏按钮上
  那个名字**。改名后按钮是「样式｜覆盖｜形态｜气候」，与需求对得上。
  语义也更顺：**地形是那三个轴本身，样式是它们合成出来的样子**（88 个显示类，一格一名一色）。
  `k` 仍是 `"terrain"`：**本地存档、键盘 4 号位、`ui.js` 的回落值一个都没动**（不需要作废存档）。
- **新增只读层「形态」**：只看一个字节的**低 3 位**（平原/丘陵/高原/山地）。理由是「样式」层把
  三个轴合成一个名字，**山系在图上散成十几种颜色**（山地密林/山地草原/山地草甸/山地盐漠…），
  "哪一片是山地"看不出来；单轴层一眼可见 —— v8 那次**山地门槛 350 m** 的调整看的就是它。
  配色 4 色（平原浅绿→山地褐），**两两最小 ΔE 21.5**（离海洋底色 39+、离海冰色 16.7）。
- 四层顺序 `RO_ORDER = ["terrain","cover","form","climate"]`（键盘 **4/5/6/7**），
  仍是"加一层只改 `ro.js` 一张表"那条路：`ui.js`/`render.js` 一行没动。

### 3. 顺手修掉的三个真 bug

1. **海冰被当成陆地**：`buildRoStats` 的"陆地"与"形态直方图"原来只排掉「海洋」，于是
   **726,135 格海冰（占全图 7.7%）**被算进陆地、并全部计成**平原**（它的形态位恒 0）。
   现在把"那两位对它没有意义"的判据收进一个函数 `noAxis()`（= 海洋 ∪ 海冰），形态层与气候层
   都调它 —— 海冰在气候视图里原来还会被算成"寒带"，一并修掉。
   ⚠️ 于是编辑器的"陆地"从 3,718,233 变成 **2,992,098**（管线 `check_terrain` 那个"陆地"原来
   也是含海冰的数，一并分开报：陆地 2.99M ＋ 海冰 0.73M）。
2. **样式层检视器在浏览器里会抛错**：它引用 `DISPLAY_LUT.length`，而 `ro.js` 的 import 里
   **没有 `DISPLAY_LUT`** → 打开那一栏就是 `ReferenceError`（空白）。这是这次**写冒烟测试**
   （在 Node 里把四个层的 `panel/insp/rgb/bucket/bucketLabel` 全跑一遍）抓出来的 ——
   纯语法检查（`node --check`）看不出来。

3. **`display_class.usage()` 的移位是 v9 之前的旧值**（`terr >> 4, terr & 15`）：
   它在管线里只用来打印"出现在这张图上的 N 类"，所以**不报错、只报错数**——之前那次重跑说
   "出现在这张图上的 59 类"，改对之后是 **80 类**（88 类里 8 类从没出现过）。这正是那段
   代码自己注释里警告过的那种错：`cov*4+frm` 用旧移位仍落在 LUT 范围内，于是**静默**换成别的
   组合。已改成 `>> 3 / & 7` 并在 docstring 里写明"这两个移位量是契约"。
